# 展板露出核查 · 送印稿登记与瑕疵反查

印厂在原片上发现一块瑕疵时，查出它影响了哪些在印展板、在各展板上实际露出的
落版矩形（即需要补印的位置）；同时保留送印前的刊用核查。

## 启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

登记数据存放在命名卷 `boarddata`（容器内 `/app/data`），重启后仍可查。

本地开发（需 Python 3.11+）：

```bash
pip install -r requirements.txt
DATA_DIR=./data python app.py     # http://localhost:8000
python test_geometry.py           # 核心几何
python test_store.py              # 登记 / 反查 / 并发 / 重启
python test_app.py                # 网页流程（需已安装 flask）
```

## 使用

1. **刊用核查**：首页粘贴或上传 JSON，核对每幅原片的露出是否都在可刊矩形内；
   整页无缺口时出现「下载署名 CSV」。
2. **登记 / 换稿**：按展板编号登记通过核查的 JSON（文件上传或粘贴均可）。
   首次登记成为稿次 1；之后每提交一次，稿次 +1。
3. **反查**：输入原片编号和原片上的整数像素矩形（x / y / w / h），
   结果逐处列出瑕疵在展板内实际露出的落版矩形（展板坐标，x / y / w / h），
   并标明展板编号、稿次与片号。同一瑕疵露出多处就逐处列出；
   只有边缘相碰（交集面积为 0）的略过。可只查某一块展板。

## JSON 格式

```json
{
  "board": {"width": 6000, "height": 4000},
  "photos": [
    {"id": "A-001", "credit": "陈晨",
     "permit": {"x": 0, "y": 0, "w": 2400, "h": 1600}}
  ],
  "pieces": [
    {"photo": "A-001",
     "crop": {"x": 100, "y": 80, "w": 1200, "h": 900},
     "at": {"x": 300, "y": 250}}
  ]
}
```

- `board`：展板尺寸，整数像素，宽高可达 10^9。
- `photos`：原片清单。`permit` 为可刊矩形（原片坐标）。
- `pieces`：裁片，**从下往上**排列（数组越靠后层级越高）。`crop` 为原片裁框
  （原片坐标），`at` 为落版位置（裁框左上角在展板上的坐标）。
- 所有坐标为整数像素；`w`/`h` 或 `width`/`height` 均可。
- 坐标系：原点左上，x 向右，y 向下；裁片按原尺寸铺放、互不透明。

## 计算规则

- 每片裁片的可见部分 = 其落版矩形（裁剪到展板内）减去所有更上层裁片的矩形。
- 可见部分平移回**原片坐标**后，同一原片多处的重叠区域只计一次（矩形并集）。
- 露出面积 = 并集面积；缺许可面积 = 并集中落在可刊矩形外的部分。
- 只有缺许可面积为 0 的送印稿才可登记。

## 稿次与并发约定

- 登记页会在表单里带上**页面所见稿次**；提交时与当前已生效稿次比对，
  不一致（期间有人换稿）则拒绝本次提交，提示当前稿次，并保留当前稿。
- 新稿次与它的露出数据**一起生效**：先在锁外算好露出矩形，
  再在锁内校验稿次、原子写盘（临时文件 + rename）后一次性换入内存。
  写盘失败或处理失败时内存不变，旧稿继续生效。
- 反查开始时一次性取同一时刻生效的登记表，之后不再读取存储，
  因此查询期间即使有人换稿，结果仍对应同一份已生效的送印稿。
- 快照生成在锁外，生成期间旧稿照常可查、其他展板照常登记。

## 内存说明

登记与反查只使用登记时生成的露出矩形列表，**不建立像素画布**，
内存与落盘体积只随露出矩形数量增长，与展板像素尺寸无关——
宽高十万像素见方的展板同样适用。
